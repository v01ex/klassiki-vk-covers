# Обложки Классиков — исследовательский прототип VK Mini Apps

Включены 12 оригинальных PNG, галерея, выбор, скачивание и реальная проверка API через VK Bridge 3.0.2.

Опубликованный прототип: https://v01ex.github.io/klassiki-vk-covers/

Приложение ВК: https://vk.ru/app54807558

В настройках URL мобильного приложения, десктопной версии сайта и мобильной версии сайта укажите один и тот же HTTPS-адрес прототипа выше, сохраните изменения и откройте приложение внутри ВК.

GitHub Pages публикует корень ветки `gh-pages`. Для обновления после изменений в `public`:

```powershell
git add public
git commit -m 'Update app'
git push origin main
git subtree split --prefix=public -b pages-update
git push origin pages-update:gh-pages
```

Повторные обновления: используйте новое имя временной ветки вместо уже существующей `pages-update`.

**Автоматическая установка пока НЕ реализована и НЕ подтверждена.** Первый этап — проверить, выдаёт ли `photos.getOwnerCoverPhotoUploadServer` адрес загрузки без `group_id` для пользовательского токена. Необязательность `group_id` в схеме не означает поддержку личного профиля. Даже успешный ответ не доказывает, что загрузка установит шапку личной страницы. Прототип не вызывает методы сохранения, не меняет аватар и не устанавливает обложку сообщества.

## Локальный запуск

Требуется Node.js 22 или новее:

```powershell
cd D:\klassiki_media\vk-covers
npm ci
npm start
```

Галерея: http://localhost:5174. В обычном браузере проверка ВК отключена.

## Проверка в ВК

1. Создать VK Mini App в кабинете разработчика.
2. Разместить содержимое `public` на HTTPS-хостинге и указать адрес в настройках приложения. Сервер Node нужен только для локального предпросмотра; API вызывается через Bridge.
3. Открыть приложение через ВК. ID берётся из параметра запуска `vk_app_id`.
4. Нажать «Проверить возможность», предоставить разрешение `photos`, скачать результат `vk-cover-probe.json`.
5. По результату определить следующий шаг: отказ API исключает этот путь; адрес загрузки требует дальнейшего изучения назначения и разрешений прежде, чем добавлять установку.

Диагностика 2 проверяет три этапа: `VKWebAppGetAuthToken`, контрольный `users.get`, затем `photos.getOwnerCoverPhotoUploadServer` без `group_id` и параметров кадрирования. В сохранённом пользователем описании методов `saveOwnerCoverPhoto` упоминает обложку сообщества или профиля пользователя; получение адреса загрузки описано для сообщества. Реальную поддержку нужно проверить на конкретном приложении.

Токен используется только в памяти для вызовов Bridge, не сохраняется в localStorage, не отправляется нашему серверу и не попадает в отчёт. Отчёт содержит этап, тип и числовой код ошибки, признаки успеха авторизации и контрольного запроса, но не текст ошибки, данные пользователя и параметры запросов. Отмена авторизации и таймаут не считаются успехом.

Источники:
В сохранённой официальной документации `photos.saveOwnerCoverPhoto` право `photos` для пользовательского ключа указано как выдаваемое в исключительных случаях по запросу на `devsupport@corp.vk.com`. Нельзя считать, что обычная авторизация Mini App предоставляет такой доступ. Готовый текст обращения: `SUPPORT_REQUEST.md`.

- https://dev.vk.ru/ru/method/photos.saveOwnerCoverPhoto
- https://github.com/VKCOM/vk-api-schema/blob/master/photos/methods.json
- https://github.com/VKCOM/vk-bridge

Проверки: `npm test`. Они проверяют контракт запросов и отсутствие секретов в отчёте; живую установку не проверяют.
